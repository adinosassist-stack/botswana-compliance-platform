The new `cloudflare/schema/dock-hosted-staging-auth-candidate.sql` supplies the shared auth/state-read subset with a synthetic-only identity constraint and an unseeded `dock_staging_identity` marker. `cloudflare/src/general-ai-dock-fixture-adapter.js` is review-only and unmounted. Rebinding the existing AI backend requires proving it will not disrupt any other staging acceptance path; otherwise use an independently reviewed isolated backend instance.

## Executable protected inert provisioning candidate
The consolidated `Dock protected inert staging bootstrap` workflow now has three modes. `preflight` verifies the exact main/environment policy and performs offline qualification; `bootstrap-inert` creates only an absent route-free disabled workspace Worker; `provision-inert-resources` runs the new `scripts/dock-provision-inert-resources.mjs` behind the same independently protected `general-ai-private-staging` environment. Both mutation modes require an owner dispatch and exact SHA. Before dispatch independently verify the current environment policy, scoped credentials and BF-07/CI requirements. The protected environment must supply `DOCK_STAGING_BOOTSTRAP_CLOUDFLARE_TOKEN` (bootstrap), `DOCK_STAGING_PROVISION_CLOUDFLARE_TOKEN` (new D1, Access and exact hostname provisioning), `GENERAL_AI_STAGING_CLOUDFLARE_ACCOUNT_ID`, secret `DOCK_STAGING_TESTER_EMAILS` (one to five reviewed real tester emails), and variable `DOCK_STAGING_BOOTSTRAP_VERSION_ID` (independently verified 100% deployed version from bootstrap evidence). Never use a production token or broad credential merely to make a failed preflight pass.

The provision job checks account and zone, both Worker subdomains, exact inert bindings and version, account/zone Access apps, Worker domains and routes, DNS collisions and D1 name availability. It creates only `bw-dock-hosted-synthetic-staging`, applies the checked-in auth/state-read schema and identity marker only to the newly returned verified empty D1, creates a dedicated Access app with explicit tester policy, verifies Access before attaching only `dock-staging.thebedesk.com` to the inert Worker, and rechecks deployment identity and ingress. No session, AI provider binding, DB binding, origin flag or voice flag is activated. The Worker continues returning 404 while inert. Mocked orchestration tests are not live Cloudflare evidence. The job stops on any uncertainty, including an existing named resource, API read permission failure or partial inventory; do not blindly rerun after partial creation. Independently inventory run-owned resources, reconcile any partial state and approve a narrowly scoped recovery plan before continuing. No automatic destructive rollback of unknown resources.
