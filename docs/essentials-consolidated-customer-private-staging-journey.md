# Thebe Desk Essentials — ONE consolidated customer private-staging journey batch

**SOURCE ONLY · DEFAULT DISABLED · NOT DEPLOYED · NOT CUSTOMER ACCESSIBLE**

This is a single substantial continuation of merged #2712, **not a sequence of small PRs**. It adds a separate external-customer invitation + Authorization Code/PKCE backend, an unmounted customer-only HTTP gateway, and an accessible Thebe-styled full-terms acceptance page, with an isolated D1 migration *candidate* and negative qualification. It does not create or deploy the Cloudflare Worker, execute SQL, provision a registered identity provider, send invitations, or authorize any production activity.

## Full intended journey

1. **Trusted business invitation issuer:** `issueInvitation` requires independently authorized issuer action, real customer-to-quotation ownership verified against the authoritative system of record, active customer identity link and accepted **frozen quote with immutable full contractual terms**. A cryptographically random 256-bit bearer ticket and distinct OIDC nonce are minted, while D1 keeps only ticket and nonce SHA-256 hashes; the original OIDC nonce is sealed under nonextractable AES-GCM-256 with authenticated scope. One D1 `db.batch` transaction inserts the existing one-time customer invite, the encrypted launch and mandatory audit assertion that aborts both prior inserts if incomplete. The ticket is returned **only to an authorized delivery service**, not a public HTTP response.

2. **Out-of-band invite possession:** A separately approved customer delivery host must transmit a short-lived ticket to the verified customer's authorized channel. Prefer a fragment-only invitation token that browser JS immediately strips from browser history, then supplies only in a same-origin HTTPS POST JSON body to `/private/customer/invitations/:id/start`; do not put the secret into URL queries, logs, analytics, referrers, HTTP headers recorded upstream or customer support tickets. The module does **not** implement delivery/channel proof and cannot infer legal ownership from ticket possession. The link must be bound again to the independently signed external-customer IdP identity.

3. **Separate customer OIDC login:** `beginCustomerLogin` requires the exact same-origin HTTPS POST, high-entropy ticket and current immutable quote, pending invitation and customer ownership. It generates independent 256-bit `state`, browser-bound OAuth cookie and PKCE verifier. The verifier is AES-GCM sealed with authentication metadata, stored against SHA-256 state/cookie digests in the **same isolated D1**, and created in one three-statement transaction: one-time invite launch transition to `started`, guarded login attempt INSERT, and mandatory SQL audit assertion that aborts missing/zero-row intermediate writes. It emits a pinned IdP authorization URL with PKCE S256, original nonce, `prompt=login` and `max_age=0`, and `__Host-thebe-customer-oauth; Secure; HttpOnly; SameSite=Lax`. It **must never use** the separate employee OIDC session/actor flow.

4. **One-use callback:** `completeCustomerLogin` processes only the exact pinned OIDC HTTPS redirect with single `code`, `state`, `iss` parameters and matching browser OAuth cookie. It atomically consumes the state/cookie attempt before confidential code exchange, rechecks the current invite/identity link and original encrypted nonce and calls a separately configured confidential exchange interface that must enforce pinned TLS, client credentials, bounded JSON, no redirects and no token logging. **An exchanged ID token is UNVERIFIED.** Only the separately reviewed #2709 `issueVerifiedCustomerSession` must verify provider RS256 signature/issuer/audience/nonce/fresh `auth_time`, current independent customer account ownership and one-use pending invitation before issuing the real customer cookie and CSRF. Failed callback or exchange is fail closed and not silently reusable. A `loadTrustedCustomerInvitation` adapter provides the original nonce *only* to confidential internal callback code after a separate owner-authorized check, not an HTTP route.

5. **Browser/session separation:** The verified customer's primary cookie is `__Host-thebe-customer; Secure; HttpOnly; SameSite=Lax`, distinct from Thebe employee `__Host-thebe-consent`. The customer CSRF is a separate `__Host-thebe-customer-csrf; Secure; SameSite=Strict; Path=/` cookie (JS-readable and hash-checked by the boundary); the temporary OAuth cookie is cleared. Do not expose cookies, JWTs, PKCE code/verifier, invite tickets or CSRF values in logs or third-party assets.

6. **Protected no-store review:** The source-only HTTP adapter supports customer-only login start, OIDC callback, full quotation review GET and explicit accept POST. Every request is gated by **injected independently authenticated private-host access** and abuse/rate-limit authority. The full quote and immutable terms are loaded by the previously qualified #2710/#2711 customer-only boundary and rendered as complete readable UTF-8 text, HTML escaped and never truncated. Nontext PDF quotation bytes deliberately fail closed until a separately reviewed private PDF viewer is provided. Mobile-first, white/charcoal/Thebe blue styling, no gradients. CSP nonce, no-store/noindex, no external assets, frame denial, separate explicit checkbox and a true “Do not accept” action that never sends consent.

7. **Atomic explicit acceptance:** The same-origin, CSRF-checked POST uses the earlier #2710 exact 7-field payload and #2712 consolidated external-customer identity and one-use transaction. The database must atomically consume the review offer, write immutable customer-specific acceptance and signed **server-record** evidence plus audit. The HMAC authenticates the **server's** receipt integrity, **not** the customer's private signature or proof of legal consent by itself. Actual consent needs independently verifiable customer identity, presentation, intent and legal terms authority. No customer acceptance routes are mounted by this PR.
