FINAL HARDENING

What changed

Task authorization now fails closed

The task module starts without a tenant namespace and without authorization. It does not inject, read, write or render task state unless it independently confirms an Owner/Manager session and a tenant identity.

Generic workspace fallback removed

The prior task fallback could place demo task data in a generic browser-session bucket when its session lookup failed. The hardened candidate removes that fallback.

Tasks bind to the canonical site ID

The selected Site is resolved from the tenant-scoped Sites session record. A task bucket is opened only when exactly one matching Site record is found; duplicate or ambiguous visible jobs fail closed.

Stored task records are normalized

Browser-session rows are revalidated on read and write: title/owner lengths are bounded, due dates are shape-checked, status is restricted to open / in progress / done, and the 200-task cap remains enforced.

No authority creep

No Finance, payroll or employee APIs were added. The module remains sessionStorage-only and the source continues to avoid dynamic HTML sinks such as innerHTML, eval, document.write and insertAdjacentHTML.
